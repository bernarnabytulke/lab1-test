# Лабораторна робота 1. Функції та обробка колекцій (Dart)

Консольна програма розбирає, перевіряє й агрегує показання лічильників (варіант 11). Класи не використовуються.

## Запуск

```
dart pub get
dart run bin/lab1.dart
dart format .
dart analyze
```

## Структура рішення і чому саме так

- **Один файл `bin/lab1.dart`.** Програма невелика, а всі функції — незалежні й
  без стану, тож розбивати на модулі немає потреби.
- **Тип `Reading` — іменований запис (record) через `typedef`.** Класи заборонені
  умовою; запис дає іменовані поля, перевірку типів і структурну рівність без
  зайвого коду. Альтернатива — `Map<String, Object>`: відхилено, бо втрачається
  статична типізація, а помилки в назвах ключів виявляються лише під час роботи.
- **`ParseResult = ({Reading? reading, String? error})`.** Очікувана помилка розбору —
  це не виняток, тому `parseLine` повертає запис із результатом і описом
  помилки. Альтернатива — просто `Reading?`: відхилено, бо тоді втрачається
  причина, чому рядок відкинуто.
- **`tryParse` замість `parse` + `try/catch`.** Некоректні дані тут очікувані,
  а не виняткові.
- **Конвеєри `where → map → fold`** замість циклів з накопичувальною змінною;
  `StringBuffer` для складання звіту; `firstOrNull` для безпечного пошуку.
- **Поля.** Окрім п’яти полів варіанту (дата, тип послуги, попереднє, поточне,
  тариф) додано шосте — номер лічильника: на ньому демонструється регулярний
  вираз з іменованими групами й маскування через `replaceAllMapped`.
- **Похідні значення** (`consumption`, `cost`) обчислюються функціями, а не
  зберігаються в записі, щоб не було розбіжності даних.
- **Сортування:** параметр `by` (`'cost'`/`'date'`) і `ascending`.
  Рядковий ключ обрано замість `enum`, щоб не вводити нових типів, а
  неприпустиме значення викликає `ArgumentError` (це помилка програміста).
- **Регулярні вирази** — сирі рядки з іменованими групами (`kind`, `number`,
  `head`); маскування через `replaceAllMapped`.

## Залежності з pub.dev

Зовнішніх залежностей часу виконання немає: усе потрібне є в `dart:core`.

| Пакет | Навіщо | Альтернатива |
|-------|--------|--------------|
| `lints` (dev) | Набір рекомендованих правил для `dart analyze` | `very_good_analysis` — суворіший, але надмірний для цієї роботи |
| `collection` | Не підключено: `firstOrNull` та `indexed` є в ядрі, починаючи з Dart 3.0 | — |

## Замикання: що захоплюється

- `makeCounter()` повертає функцію, яка захоплює локальну змінну `count`.
  Змінна живе, доки жива повернена функція, і при кожному виклику
  збільшується на 1. У `main` лічильник рахує оброблені рядки.
- `consumptionAbove(threshold)` захоплює параметр `threshold`; повернений
  предикат перевіряє `consumption(reading) > threshold`. Використовується у фільтрі `where`.
